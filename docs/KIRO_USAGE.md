# How Kiro is used in GhostCheck

This file is the "how Kiro was used" write-up required by the Kiroween rules. It is updated as the project is built and records who produced what.

| Kiro feature | Where | Status (2026-11-05) |
|---|---|---|
| Steering | `.kiro/steering/` — `product.md`, `tech.md`, `structure.md`, `security.md` (all `inclusion: always`) | Written by the team as Kiro steering files |
| Spec-driven development | `.kiro/specs/site-seance`, `ai-seance`, `haunted-ui` | `requirements.md` written by the team in EARS form; `design.md` and `tasks.md` generated by Kiro CLI 3.0.0 from them on 2026-11-05 (unedited) |
| Agent hooks | `.kiro/hooks/` | Created by Kiro CLI 3.0.0 on 2026-11-05: `run-tests-on-save` (fileEdited → vitest unit + property tests), `secret-scan` (agentStop → scan changed/staged files for key patterns; Kiro has no git pre-commit event), `readme-check-table` (fileEdited in `packages/core/src/checks/` → refresh README check table) |
| Property-based testing | `packages/core` (fast-check) | Planned: RFC 9309 robots.txt matching, score bounds and monotonicity |
| MCP | Kiro MCP config | Planned: a fetch/browser MCP for regression runs against real public sites (to be verified in Kiro) |
| IDE / CLI | Kiro IDE for specs; CLI for task runs | Kiro IDE 1.4.86 and Kiro CLI 3.0.0 installed 2026-11-05; specs generated with the CLI |

## Division of work
- **Humans (with AI writing help):** product decisions, steering, requirements, review of every Kiro change.
- **Kiro:** design documents, task lists, application code, tests and hooks.
